# Bread AI 长输入、输出截断与上下文恢复设计

## 采用的公开设计

本轮查阅了以下项目的原始源码/官方文档，并结合本项目固定的 DeepAgents
0.7.22 实现验证。链接是研究当日的公开分支；Bread 没有因此升级依赖。

| 项目 | 公开实现中的处理方式 | Bread 的采用方式 |
| --- | --- | --- |
| [DeepAgents](https://github.com/langchain-ai/deepagents/blob/main/libs/deepagents/deepagents/middleware/summarization.py) | 根据模型窗口、输出预留和完整请求计数压缩；原历史卸载到文件；输入被拒后只重试变小的请求 | 继续使用固定框架的摘要、工具结果卸载、检查点及溢出恢复；补上连接元数据和恢复边界 |
| [Gemini CLI](https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/context/chatCompressionService.ts) | 保护近期工具结果；大结果落盘；检查压缩是否有效；避免反复失败的压缩 | 保留近期上下文与精确文件引用；使用框架的请求缩小检查，并保留空转检测 |
| [Aider 的输出处理](https://github.com/Aider-AI/aider/blob/main/aider/coders/base_coder.py)、[历史摘要](https://github.com/Aider-AI/aider/blob/main/aider/history.py) | 识别长度终止；是否直接续接取决于模型能力；摘要旧历史并保留近期消息 | 使用同一任务检查点续作，提示分段文件输出；不假设所有接口支持 assistant prefill |

[OpenAI 服务端压缩](https://developers.openai.com/api/docs/guides/compaction#server-side-compaction)
也提供了保留状态的压缩路径，但并非所有兼容网关都支持相同参数。本轮没有
给所有服务商强加该接口，而是在已使用的 Agent 框架中完成通用处理。

## 输入侧

### 实际使用模型窗口

`context_management.configure_model_context` 将可核实的窗口接入正在运行的
LangChain 模型 `profile.max_input_tokens`，保留原有工具/多模态能力元数据。
优先级为：当前模型的显式配置、SDK 元数据、已有模型目录、用户显式配置的
回退值。未知别名仍可以发请求，不捏造它的窗口大小。

预算扣除已配置的单次输出额度和框架安全余量；摘要触发阈值、近期保留范围
及摘要输入本身的长度随预算调整。计数包含系统文本、固定任务引用和工具
定义，采用保守的本地估算，避免只计算聊天正文。估算不等于服务商精确分词。

未知窗口的别名使用有界近期消息与有界摘要输入，依靠明确的服务端上下文
错误触发恢复。不会把六条超大工具结果简单当成可安全保留的尾部。

### 首条输入本身过大

历史压缩不能解决没有旧历史可压缩的超长首条消息。因此：

- API 在当前授权工作区的隐藏上下文目录中保存精确 UTF-8 原文，按 SHA-256
  命名。模型接收注明不完整的预览及分页/搜索入口，原文中间的约束仍可查回。
- 主 Agent 的模型调用持续携带原始任务引用；短请求还携带引号编码的原文。
  用户文本保持用户优先级，不提升为系统指令或新的 Host 效果授权。
- 原生 ACP/Codex 通过私有控制文件将原文送到已有任务 MCP，使用固定的
  `bread-task-input://request` 入口调用 `read_evidence_file`。这条路径不依赖
  原生 Read 或 Shell，也不扩大任何目录读取权限。
- MCP 验证输入描述文件的 schema、文件类型、大小、字节数与 SHA-256。
  读取使用本任务的存储与 UTF-8 字节分页；相邻任务无法借同名入口读取它。
- 输入控制文件是隐藏的启动资料，不列为用户交付文件；原有用户文件不会被
  覆盖或改名。正常结束时按已有任务清理规则处理。

图片、PDF 等原生附件仍使用原来的媒体链路，不静默删掉或改写证据来宣称
输入已解决。

### 历史增长及被服务端拒绝

DeepAgents 负责摘要旧消息、卸载大工具结果并保留回读路径。Bread 补充摘要
要求：保留用户约束、捕获/目标身份、源码路径与哈希、已完成收据、未结束
作业和下一步；不得将失败或 pending 状态改写成完成。

某些 SDK（例如 Google）的错误用数值 `code` 和 `response_json` 表达，未必
有 `status_code`。新增处理仅归一化明确的输入/上下文错误，让框架在当前
模型调用内部压缩和重试；不会重启整个任务或再次执行此前的工具。
鉴权、权限、限流、通用 413、输出参数配置错误不当作输入溢出来压缩。

另一个实测边界是：长工具链按角色裁剪后可能没有任何可供摘要的用户消息，
框架于是只返回“历史太长”的占位文本。现在这种情况下会给摘要调用提供
有长度上限、标明不完整的角色/调用/内容摘录；精确完整历史仍走正常卸载
路径。摘要仍是有损信息，重要原文和收据可按路径重新读取。

## 输出侧

API 主任务继续复用当前图、检查点与工具会话，有新答案或新工作就可以跨
多次请求推进。连续空转、真实错误、取消和已配置的总运行时限分别处理；
不调整用户的 API Key、服务商、模型或收费相关的输出/推理档位。

对输出截断时返回的工具提案增加执行前保护，覆盖主 Agent 和 API 子 Agent：

1. 若该条模型回复报告长度终止且带有工具调用，整条提案先保存为诊断资料。
2. 该条回复中的工具都不执行，包括 SDK 恰好把部分 JSON 修复成可解析参数
   的情况。不会把截断源码写到正式工作区或用半截参数运行效果操作。
3. 检查点保存明确的“提案未执行”记录，不留下悬空的工具调用或历史参数。
4. 主 Agent 在确认没有实际待执行节点后继续，要求生成较小的完整调用和
   增量文件编辑；子 Agent 将未执行记录交回主 Agent，由其恢复剩余工作。

不是把半截 JSON 强行补齐后执行。已完成工具的收据仍在原上下文中，运行时
不会重发原始任务以重放它们。请求的效果授权、源码 CAS、捕获身份等原校验
保持有效。

## ACP 与 Codex

原有 `max_tokens` / `max_turn_requests` 同会话续作继续使用；长输入共用新的
任务 MCP 分页入口。SDK/RPC 明确返回的上下文错误可归一化为 `provider-context`。

ACP 的压缩恢复遵循[命令声明协议](https://agentclientprotocol.com/protocol/v1/slash-commands)：
只有当前供应商会话明确声明 `compact`，且没有未结束工具时，才发送 `/compact`。
维护用的压缩文本不会冒充最终答案。压缩后继续原任务，不重发原始长输入。
同一工作指纹仍然被拒绝时不反复压缩；没有声明能力、鉴权错误或工具未结束
时也不会猜测私有接口。Codex 的长会话内部压缩仍由其 Agent 实现管理。

## 验证场景

使用真实固定依赖和本地模型/协议模拟服务验证，未调用用户或对方的真实
模型账号：

- 同一连接中不同模型的窗口配置优先级，SDK 能力元数据和原配置保留。
- 长首条输入中间的中文约束可通过实际工具找回。
- 历史预压缩、Google SDK 形状的上下文错误恢复、摘要后原始任务仍可见。
- 精确旧历史文件仍含早期证据；完成的八次工具操作没有被重复执行。
- OpenAI Chat / Responses / Anthropic 的真实 SSE 解析：空文本截断，以及
  工具参数截断后恢复，已完成的工具收据仍在后续请求内。
- 主/子 Agent 的截断工具提案不会执行；正式文件通过有界的 write/edit
  分段形成，实际输出内容完整并在任务结束后保留。
- ACP 声明、撤销及跨会话命令通知；压缩输出不进入用户答案；不支持、再次
  超限和鉴权失败不会引起恢复死循环。
- 无 capture、无 Host、无原生 Read 的真实 MCP stdio 进程中，长输入通过
  直接工具及延迟分发两种入口分页，UTF-8、哈希和本任务读取范围保持正确。
- 原生输入描述文件不会被误报为用户交付物；既有文本、图片、权限、取消和
  工具输出回归一并检查。

最终通过数量和命令记录在[链路检查报告](AI_OUTPUT_CHAIN_AUDIT_2026-11-11.md)。
修改保持在本地未提交分支，未打包、发布或替换其他任务的应用安装。

## 实际边界

这些恢复机制不能取消模型的服务端硬上限。若固定系统/工具定义、单个不可
分割的媒体输入或必须逐字保留的输入本身仍无法装入模型，仍需保留具体错误，
而不能无限重试或伪造完成。摘要也不保证零信息损失；本实现通过固定原任务
引用、精确原文/工具文件与 Host 收据，使关键细节能够重新读取和核对。
逐家供应商的线上可用性与真实推理质量仍需各自账号、版本和现场数据验证。
