## 输入证据与原因

检查用户提供的 `8bd07d4d101b457c93fefe7f7f1d62c6.jsonl`、
`e02905164eb945cabc3d3c449a8423f5.jsonl` 及界面截图。原始文件未改写或收录到仓库。
两份日志都由 Agent 正常结束并报告 `partial`，不是传输本身异常退出。
日志只记录部分工具状态和公开回复，不能冒充完整的 Host 原始诊断或实际 RDC。

- 普通 D3D11 Draw/DrawIndexed 的 `numInstances` 默认是 0，只有带 `Instanced`
  标志的调用才有实例数量操作数。原来的 outline、详细工作量及 Host 分类都把它当作
  实际实例数，误报零工作量并阻止流程图发布。现在按原生标志解释；真实零索引、
  零实例化实例数及未解码的间接参数仍保留原有阻断/未知状态。相同问题也影响
  post-VS 网格观察，已一并修正；检查会恢复原选中 EID。
- RenderDoc 保留 DXBC 的原始 ReadWriteMask：输出签名表示“从未写入”的分量，
  所以声明 xy、掩码 zw 是合法组合。Host 原来要求它必须是声明掩码的子集。
  现保留原始位供旧记录重读，只对输入保留子集检查；输出的寄存器、类型、
  分量数及完整物理 ABI 检查仍有效。掩码一直不参与物理 ABI 哈希。
  语义依据：[Microsoft D3D11_SIGNATURE_PARAMETER_DESC](https://learn.microsoft.com/en-us/windows/win32/api/d3d11shader/ns-d3d11shader-d3d11_signature_parameter_desc)。
- 冻结上下文后的排队请求，在正式启动时曾遇到桥接心跳过期就立即失败。
  现在复用已有的有界桥接等待参数，保留原会话/EID 和同对话顺序；其他对话仍可启动。
  不同会话、关闭捕获或超时仍进入原有身份校验。修改排队请求时重置等待期限。
  这是源码中确认的恢复缺口，截图缺少完整现场数据，不能断言它解释所有桥接失败。
- 项目原子写入使用短的同目录暂存名，避免把长目标名再拼 UUID 后超过路径/分量限制。
  目标路径、项目数据和内容不改名；事务日志保留原来的目标绑定暂存名及崩溃恢复规则。
  附件未包含项目临时文件失败的完整系统错误，因此无法确认现场是否还有 ACL、磁盘或
  其他路径问题。

AI 任务不能写入并热加载宿主代码的权限边界保持原状。修复宿主的固定算法，
不会让模型为完成分析而修改安装目录、扩大沙箱或在活动任务中编辑连接。

后续同类排查又修正了符号目录中的输出掩码子集误判，避免工作区 ABI 校验通过后，
目录仍把合法接口当作不完整。顶点数值 A/B/A 验证也不再把真实零实例数量提升为 1。
新增 Windows、Ubuntu、macOS CI 矩阵，检查 D3D11/D3D12/Vulkan/OpenGL 共享规则和
API/Codex/ACP 链路；这是跨系统的工具与证据契约验收，不冒充三系统真实 GPU 回放。

## 日志结构与测量

现有任务日志不是按大小轮转：每次用户请求生成一个 task 文件，自动续轮仍使用同一文件。
提供商逐 token/字符发送的增量曾原样逐条写入，每条重复完整 JSON 上下文。

现在公共流统一经过最多 100ms / 8192 字符的相邻增量合并。元数据只在同一批中复用；
不同消息、代理、推理通道、重置、结束事件和工具边界不会合并。结束前同步清空，
保留原 v1 读取、跨进程序号和终态 fsync/幂等协议。新 queued 事件加入 conversationId，
可关联同一对话的多轮 task；不搬迁或覆盖旧日志。读取规则见 `ARCHITECTURE.md`。

用附件的原始事件时间模拟 100ms 合并窗口，向系统临时目录重放同一生产写入逻辑；
比较规范化事件后，所有文本和元数据一致。只重新分配持久事件序号/写入时间。

这是附件重放的结果，不是所有模型/网络节奏下的固定压缩率。进程被直接杀死可能丢失
